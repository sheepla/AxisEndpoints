## What Is an Endpoint Group?

An Endpoint Group is a mechanism for letting multiple endpoints share a common route prefix, tags, authorization policies, and filters. It corresponds to ASP.NET Core Minimal API's `MapGroup()`, and AxisEndpoints exposes it declaratively through the `IEndpointGroup` interface.

Using groups provides several benefits:

- **DRY**: Shared route prefixes and tags are defined in one place instead of repeated on every endpoint
- **Consistent authorization**: Authorization policies defined on the group are applied automatically to all endpoints in the group
- **Consistent OpenAPI tags**: Group-level tags keep related endpoints organized together in the OpenAPI document

## The `IEndpointGroup` Interface

```csharp
public interface IEndpointGroup
{
    void Configure(IEndpointGroupConfiguration config);
}
```

Use `IEndpointGroupConfiguration` inside `Configure()` to declare shared settings.

## Available `IEndpointGroupConfiguration` Settings

| Method | Description |
| --- | --- |
| `Prefix(string prefix)` | Sets a shared route prefix for every endpoint in the group |
| `Tags(params string[] tags)` | Sets OpenAPI tags |
| `AllowAnonymous()` | Allows access without authentication |
| `RequireAuthorization(params string[] roles)` | Restricts access to users who have any of the specified roles |
| `RequireAuthorization(string policy)` | Applies a named authorization policy |
| `RequireAuthorization(Action<AuthorizationPolicyBuilder> build)` | Applies an authorization policy built dynamically |
| `AddFilter<TFilter>()` | Applies a filter to every endpoint in the group |

## Basic Usage

Implement `IEndpointGroup`, then reference it from an endpoint's `Configure` method with `config.Group<TGroup>()`. The group's prefix, tags, authorization policies, and filters are shared by every endpoint that references it.

```csharp
public class UsersGroup : IEndpointGroup
{
    public void Configure(IEndpointGroupConfiguration config)
    {
        config.Prefix("/api/users")
            .Tags("Users")
            .RequireAuthorization("CanManageUsers");
    }
}

public class GetUsersEndpoint : IEndpoint<Response<GetUsersResponse>>
{
    public void Configure(IEndpointConfiguration config)
    {
        // Resolves to GET /api/users
        config.Get("/").Group<UsersGroup>().Summary("Get all users");
    }
    // ...
}
```

:::note
Calling `.RequireAuthorization()` with no arguments requires an authenticated user without restricting to any specific role or policy. To restrict further, pass a policy name, such as `RequireAuthorization("CanManageUsers")`, or one or more role names, such as `RequireAuthorization("Admin", "SuperAdmin")`. Passing a single string selects the `string policy` overload, so it is interpreted as a policy name rather than a role.
:::

:::note
"Per-endpoint settings take precedence" means an endpoint's own authorization setting — whether
`AllowAnonymous()`, `RequireAuthorization()`, a role list, a named policy, or a custom policy —
fully replaces the group's, rather than being combined with it. An endpoint that declares no
authorization setting of its own inherits the group's setting unchanged. This is a deliberate
choice by AxisEndpoints: plain ASP.NET Core Minimal APIs would instead AND multiple
`RequireAuthorization` declarations together when they are applied at different levels of the
same endpoint, which would make it impossible for a single endpoint to opt out of a group's
policy.
:::

## Role-Based Group Authorization

```csharp
public class AdminGroup : IEndpointGroup
{
    public void Configure(IEndpointGroupConfiguration config)
    {
        config.Prefix("/api/admin")
            .Tags("Admin")
            .RequireAuthorization("Admin", "SuperAdmin");
    }
}
```

## Applying Filters to a Group

Filters registered on a group are applied to every endpoint that belongs to that group.

```csharp
public class AuditedGroup : IEndpointGroup
{
    public void Configure(IEndpointGroupConfiguration config)
    {
        config.Prefix("/api/audited")
            .AddFilter<AuditLogFilter>();
    }
}
```

For group-level authorization, see the [Authorization](/guides/authorization/) guide. For applying filters to an entire group, see the [Filters](/guides/filters/) guide.
